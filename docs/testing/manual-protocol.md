# Physical-device accessibility and UX protocol

All checks begin pending in manual-acceptance.json. Record real hardware, Android/browser/TalkBack versions, reviewer, ISO review time and evidence references. Never fill passed from a mockup, source inspection, browser emulation or a generated narrative.

1. **talkback-reading** — Enable TalkBack, open a batch question, swipe through title/progress/question/editor/tools/navigation. Expected: one meaningful reading sequence; English UI, Persian question language recognized, numerator/denominator and active step identified. No unlabeled icon or duplicate interactive stop. Record speech transcript or video.
2. **talkback-editing** — Enter a multi-digit numerator and denominator with touch exploration/double-tap. Move and delete in the middle of a number, insert a root, Undo. Expected: caret/edit context remains understandable, correct token changes, question is unchanged and work is not lost.
3. **talkback-modal** — Open confidence through Next, select radio without committing, submit blank once, fix error, cancel, reopen, continue; repeat at completion. Expected: focus enters modal, background inaccessible, error announced once, choice/required state clear, focus restored on cancel, next question announced on commit.
4. **android-touch** — Use one hand and large-finger taps at 320/390/430 logical widths where available. Test quick templates, Backspace, More tools, reset, protected first deletion, later deletion and Add step. Expected: no accidental neighboring activation, no drag/hover-only essential action, controls remain reachable.
5. **android-text-and-zoom** — Increase Android font size/display size; test actual browser 200% and 400% zoom/reflow where supported. Include text-spacing overrides and landscape. Expected: no lost labels/actions; ordinary content fits one scrolling axis; long mathematical structures may scroll locally; no forced orientation.
6. **android-safe-areas** — Test browser top/bottom toolbar expanded and collapsed, punch-hole/notch, gesture navigation, keyboard opening/closing and short viewport. Expected: app does not paint a fake OS status bar; focus, Add step and navigation are never covered. Capture portrait/landscape evidence.
7. **external-keyboard** — Connect a real Bluetooth/USB keyboard. Operate all actions without touch: Tab/Shift+Tab, arrows, / picker, Enter/Space, Escape, Undo/Redo. Expected: consistent focus, no trap outside active modal, no focus loss after deletion, no browser-shortcut hijacking outside editor.
8. **clipboard-recovery** — Grant and deny clipboard access, then export during early and final questions. Expected: success only after actual copy; failure gives selectable JSON; every question/step/time/confidence is preserved, no answer-bank keys. Import backup and compare original work.
9. **multi-tab-recovery** — Open two same-origin tabs, edit clean remote tab, create simultaneous unsaved edits, choose both conflict outcomes in separate trials; reload after quota/corrupt-data failure. Expected: no silent loss or endless sync echo; legacy draft retained; recovery/export available. No claim of cross-device sync.
10. **contrast-review** — Review actual rendered text, icons, border/error/focus states, selected radios, disabled delete and forced-colors. Check regular text ≥4.5:1, large text ≥3:1, essential control indicators ≥3:1 where applicable. Disabled controls have WCAG contrast exemptions but must remain understandable. No state relies only on color; no flashing content.
11. **visual-baselines** — Review real browser captures for each phone project and single/batch/confidence states. Confirm approved keypad order, = last, Add step placement, icon controls, no inline confidence, batch footer versus single footer, enlarged keys in surplus height. Create snapshot files only after visual review. Never approve via --update-snapshots alone.
12. **axe-incomplete-triage** — Read every incomplete/manual-review result in browser axe artifacts, verify each rendered instance and record disposition/evidence. Zero automatic violations does not close manual items.

If a criterion fails, record status failed with reproduction steps and evidence; do not omit it. An untested case remains pending. A complete checklist is not sufficient if automated gates or snapshots are failing.
